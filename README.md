## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.

## Braviel admin workspace

The admin workspace starts with no sample users or business records. Apply the database migrations, then create the first administrator from an interactive terminal:

```powershell
php artisan migrate
php artisan app:make-admin admin@example.com --name="Workspace Administrator"
```

If that account does not exist, the command prompts for a password and confirmation without echoing either value. To promote an existing account instead, pass its email to the same command. The user-management screen supports username, name, role, and email search, paging, CSV and Excel-compatible XML exports, printing, and browser-based PDF printing. Existing users receive a unique username derived from their email address when the username migration runs; usernames can be changed from user management or My Profile.

Products, units, brands, categories, sales, inventory, stock transfers and adjustments, purchases and purchase returns, customers, suppliers, expenses, payments, returns, cash register entries, and system settings have add/edit/delete forms. Product brand, category, and unit selections use records created in their corresponding management lists; add those records before assigning them to products. Product, opening-stock, and contact imports accept CSV or `.xlsx` files; the first row of the first worksheet must contain the column names shown on the import page. Contact imports also require a `type` column set to `customer` or `supplier`. Reports are calculated from entered records; audit logs are generated automatically; workspace backups are downloaded as JSON and exclude passwords.

The Roles page includes editable permission selections for every sidebar module. The Administrator and Staff roles are built-in and cannot be deleted; custom roles can be assigned from the user form. Permission selections are stored with each role; workspace pages require sign-in, but access is not yet restricted by individual role permissions.
